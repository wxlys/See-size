# SeeSize

备份状态面板支持查看最近任务结果和文件数量，需配置 Hub 的 `-backup-dir` 并使用新版备份程序，详见 [备份状态说明](docs/BACKUP-STATUS.md)。

设备管理新增“删除设备及历史”：先撤销凭据，再输入完整 ID 确认；不会删除备份或卸载远端 Agent。详见 [设备删除说明](docs/DEVICE-DELETION.md)。

网络口径配置：Agent 支持 `-network-interfaces eth0`，空值兼容全部非回环网卡合计。页面显示当前接口及缺失警告，详见 [网络口径说明](docs/NETWORK-SCOPE.md)。新增协议字段需先升级 Hub，再升级 Agent。

当前运行环境已于 2026-09-17 从即将回收的 18 迁至 wsrser，详见 [迁移记录](docs/MIGRATION-20260917.md)。本地预览仍为 18082，新远端端口为 18081；历史部署文档中的旧路径不适用于新主机。

SeeSize 是一个面向个人开发者和小型服务器集群的轻量资源监控与磁盘异常定位系统。

当前仓库包含第一个纵向原型：

- `seesize-hub`：接收 Agent 心跳，持久化历史指标，并提供内嵌 Web 总览与趋势图。
- `seesize-agent`：采集主机信息和基础资源指标并主动上报。
- `internal/model`：Hub 与 Agent 共用的协议模型。
- `internal/collector`：Linux 指标采集及其他平台的开发占位实现。

当前验收状态与剩余测试见 [验收计划](docs/ACCEPTANCE-PLAN.md)。24 小时基础挂测已通过，不代表压力、安全部署和所有页面功能均已验收。

## 本地运行

备份与恢复已支持手动和周期执行，详细参数、恢复步骤及数据范围见 [备份手册](docs/BACKUP.md)。

Linux systemd 服务安装、开机启动、自动重启及维护步骤见 [部署手册](docs/DEPLOYMENT.md)。

### 登录与设备接入（当前版本）

Hub 启动必须设置 `SEE_SIZE_ADMIN_TOKEN`（至少 16 字符的独立随机凭据）。首次访问跳转到登录页；输入管理凭据后创建 8 小时 HttpOnly、SameSite=Strict 会话。退出立即失效，Hub 重启后需要重新登录。当前为单管理员凭据登录，不是多用户账号体系；没有角色权限或找回密码。

登录后在“设备管理”输入 Agent ID 并生成一次性注册码（10 分钟有效）。在目标主机设置环境变量 `SEE_SIZE_ENROLL_CODE`，运行 `seesize-enroll -hub <Hub地址> -id <设备ID> -out agent.token`，再启动 `seesize-agent -hub <Hub地址> -id <设备ID> -token-file agent.token`。扫描程序也支持 `-token-file`。Linux 凭据文件创建权限为 0600；Windows 需自行限制目录 ACL。

注册文件必须不存在，失败时可能留下空文件，重试使用新文件名；若兑换成功但未能保存凭据，重新生成注册码。注册成功会替换该 ID 原有凭据。撤销后停止接受该设备上报，历史数据和服务器记录保留；再次注册可恢复。数据库仅保存设备令牌及注册码的 SHA-256 摘要。

旧 `-agent-token` 仅作为显式迁移兼容项，默认不需要配置；已注册设备不能用共享令牌上报。测试机已迁移到独立凭据并停用共享令牌。HTTP 仅用于本机或 SSH 转发，公开部署须另配 HTTPS；不能将当前本机预览模式当作公网部署方案。代理 TLS 终止时启用 Hub 的 `-secure-cookies`；真实 HTTPS 部署仍待验收，见 [部署手册](docs/DEPLOYMENT.md)。

### SSH 预览恢复

测试机 Hub 只监听远端本机地址。浏览器访问 `http://127.0.0.1:18082` 依赖 SSH 转发，转发退出后会出现读取失败，但远端监控可能仍正常。在 PowerShell 7 运行 `./scripts/preview.ps1` 并保持终端打开；脚本断线后重试，Ctrl+C 停止。不要与已有同端口转发重复启动。

### 扫描节流

Agent `-scan-rate 1000` 或独立扫描程序 `-rate 1000` 控制元数据处理速率，默认每秒 1000 个条目。降低速率会增加扫描时间，必要时相应调整软超时；超时仍标为不完整，不生成告警。目录按每批 64 项读取，遍历深度上限 128 层，达到限制标为不完整。这不是磁盘 MB/s 的硬限速：系统调用和缓存行为仍可能造成瞬时 IO 峰值，操作系统级 IO 优先级控制仍待实现。

要求 Go 1.27 或更高版本。

先设置 `SEE_SIZE_ADMIN_TOKEN` 为至少 16 字符的随机管理凭据，再启动 Hub。以下共享 Agent Token 命令仅用于本机旧版链路兼容；正式接入请使用上方的注册流程：

```bash
go run ./cmd/hub -agent-token dev-secret -data .data/seesize.db
```

再启动 Agent：

```bash
go run ./cmd/agent -hub http://127.0.0.1:8080 -token dev-secret -interval 10s
```

打开 `http://127.0.0.1:8080` 查看服务器列表。默认只监听本机地址；共享 Token 仅用于旧版兼容联调，正式部署使用已实现的一次性注册码和每台设备独立凭据。

历史指标接口：`GET /api/v1/servers/{agentID}/metrics`。可选参数 `from`、`to` 使用 RFC3339 时间，`limit` 范围为 1–5000；默认返回最近一小时数据。

## 目录空间扫描（手动触发）

在被监控服务器运行配套的 `seesize-scan`，指定目录与已有 Agent ID。扫描只读取目录和文件大小，不读取文件内容。上报凭据可通过环境变量 `SEE_SIZE_AGENT_TOKEN` 提供。

```bash
seesize-scan -root /var/log -id your-agent-id -hub http://127.0.0.1:8080 -depth 3 -max-entries 20000 -timeout 15s
```

不提供 `-hub` 时，仅输出本地 JSON。构建入口为 `go build ./cmd/scan`。面板的“目录空间分析”展示最近扫描及两次完整扫描的增量。默认不定时扫描，当前显示每台服务器最近扫描根目录的最后两次结果。统计逻辑大小，符号链接不跟随，硬链接按路径计数；因此结果不等于 `df` 的物理占用。数量或软时间预算耗尽时保留部分结果并停用增量判断。已实现条目速率节流，未实现磁盘字节级 IO 硬限速，建议先扫描较小目录。

数据清理、备份及进一步的扫描优化见 [后续优化](docs/ROADMAP.md)。

## 资源趋势时间范围

图表支持最近 30 分钟、1 小时、24 小时，分别以 5 秒、10 秒、240 秒时间段聚合，最多 360 点。查询选定范围内的全部原始样本，没有最新 1000 条的截断。每段展示样本算术平均值（不是时间加权平均）及最大值。没有记录的时间段不补零、曲线断开；横轴按实际时间定位并显示已有数据范围。原始数据不修改，Agent 采样频率不改变。

接口：`GET /api/v1/servers/{agentID}/trend?range=30m|1h|24h`。`average` 和 `peak` 数组依次表示 CPU%、内存%、磁盘%、下载 B/s、上传 B/s。旧 `/metrics` 原始样本接口保留，默认上限仍为 1000，图表已不使用它。聚合目前查询时执行，后续可增加预聚合优化多节点查询负载。

## 定时扫描配置

Agent 可通过 `-scan-root /var/log` 启用定时扫描；默认关闭。`-scan-interval 30m` 表示每轮结束后等待 30 分钟（最短 1 分钟）。扫描独立于基础心跳执行，单个 Agent 内不会重叠。`-scan-timeout 15s`、`-scan-depth 3`、`-scan-max-entries 20000` 控制软时间、展示深度和条目预算。不要同时为同一目录运行多个扫描进程。失败后等待下一周期重试，不进行持续快速重试。

Hub 用 `-disk-growth-mib 100` 设置每次比较的增长提示阈值，默认 100 MiB。面板在“目录空间分析”中展示超过阈值的目录及两次扫描时间。需要同一目录、同一深度、两次完整快照；提示代表区间净增长，不是瞬时峰值或原因判定。父子目录增量重叠，不能相加。最近比较会随扫描更新，独立告警历史会持久保留至到期，支持人工确认；尚无外部通知推送。

## 告警事件

新上传的完整快照触发增长阈值后，事件与快照在同一事务中保存。重复上传不重复生成，事件不会被后续正常扫描覆盖；不回填功能启用前的历史。乱序快照保留，但不会重算已生成的事件。事件包括根目录、相对目录、增长量、阈值和比较时间范围。

面板“告警历史”每页 100 条，可查看更早事件。启动 Hub 必须配置独立管理凭据 `SEE_SIZE_ADMIN_TOKEN` 或 `-admin-token-file`（至少 16 字符，不可与共享 Agent 凭据相同），未配置会拒绝启动。登录后可标记事件已处理，当前为单管理员会话，不是多用户账号体系。

处理仅表示人工确认，不能证明空间恢复。当前页面使用登录会话执行确认，不再重复输入管理凭据。事件与指标采用相同保留天数，未处理事件到期也会删除；没有外部通知或处理人账号审计。父子目录事件增量重叠，不可相加。

## 到期清理配置

Hub 默认保留最近 7 天的指标与磁盘快照。可使用 `-retention-days 1` 改为 1 天（范围 1–365 天）。启动时及每 10 分钟检查一次，可用 `-cleanup-interval 10m` 调整。每批每表最多删除 1000 条，单轮最多运行 30 秒；积压数据在后续轮次继续清理。离线服务器清单不会删除。过期以采集／快照时间为准，需要服务器时钟准确。

清理是永久删除，不会自动备份；缩短保留期限前请确认数据需求。SQLite 删除后空闲页供后续写入复用，文件不会立即缩小；目前不自动执行整库压缩。到期数据可能在下次清理前短暂保留。独立备份已实现；长期存储分层降采样尚未实现。

## 当前边界

- Linux Agent 能读取 `/proc`、`/etc/os-release` 和根文件系统容量。
- Windows 等非 Linux 平台只能用于开发联调，上报主机名、操作系统和网络地址。
- Hub 使用本地 SQLite 持久化服务器状态和原始历史指标，重启后数据保留。
- 已支持手动目录扫描、快照保存与完整快照增量比较。
- 已支持历史到期清理、可选定时扫描、目录增长事件管理、备份恢复、单管理员登录及独立设备凭据。长期分层降采样和多用户权限尚未实现。
