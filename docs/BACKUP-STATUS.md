# 备份状态面板

Hub 新参数 `-backup-dir /path/to/backups` 指向专用备份目录。默认未配置，页面明确显示未知，不猜测备份是否运行。`GET /api/v1/backup-status` 要求管理员会话，只读状态与文件元数据，不提供触发、下载或恢复入口。

新版 backup 命令在创建备份时，向该目录原子发布 status.json：开始写 running，结束写 success 或 failed，包含开始/结束时间、本轮生成文件名、保留份数与清理份数。验证或恢复命令不写此状态。一个目录只允许一个备份写入进程，与现有备份约束一致。

面板分别展示现有备份数量/字节数与最近任务结果。只计数符合工具时间戳命名的普通 .db 文件，忽略 partial 和其他文件；文件计数不等于重新验证。文件存在但状态缺失或损坏时显示“最近结果未知”；目录读取失败独立显示错误，不延用成功提示。

强制终止、断电或状态文件无法写入可能留下 running 或较旧记录。面板显示时间并提示需检查日志，不将其当作可靠的进程存活探测；无法读取 systemd 的下次执行时间。成功记录代表当时创建、验证与保留清理流程成功，不保证文件后来没有损坏，也不能代替恢复演练。多目录互相独立，手动升级备份目录不计入日常目录状态。

Hub 需要目录只读权限，backup 需要写权限。升级需同时部署新版 Hub 与 backup，并设置 Hub 的 -backup-dir；旧 backup 不产生状态文件，直到新版首次执行前显示未知是预期。不要为查看状态提高服务权限或开启公网目录浏览。
